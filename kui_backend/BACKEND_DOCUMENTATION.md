# Архитектура и Документация Серверной Части (Backend)
**Проект:** Kuyshim (Мобильное приложение для обучения игре на домбре)

Данный документ описывает структуру, логику и архитектурные решения серверной части (Backend), разработанной на базе фреймворка FastAPI. Эта документация может быть использована в качестве приложения или главы для дипломной работы.

---

## 1. Технологический Стек
Серверная часть построена на современном стеке технологий Python:
* **Фреймворк:** FastAPI (выбран за высокую производительность, асинхронность и автоматическую генерацию OpenAPI документации).
* **База данных:** PostgreSQL (основная СУБД) с возможностью использования SQLite для локальной разработки.
* **ORM (Object-Relational Mapping):** SQLAlchemy 2.0 (позволяет работать с базой данных через объекты Python).
* **Аутентификация:** JSON Web Tokens (JWT) и библиотека `passlib` для безопасного хеширования паролей (алгоритм bcrypt).
* **Контейнеризация:** Docker и Docker Compose для быстрого развертывания связки "Сервер + База Данных".

## 2. Структура Проекта (Директория `kui_backend/`)

Ниже представлено описание каждого ключевого файла и его роли в системе.

### `main.py`
**Точка входа в приложение (Entry Point) и маршрутизатор API.**
* Инициализирует FastAPI приложение и настраивает CORS (Cross-Origin Resource Sharing).
* Подключает статические файлы (папка `storage/`), чтобы мобильное приложение могло скачивать аудио, изображения и аватарки.
* Определяет все **API эндпоинты (маршруты)**:
  * **Auth:** `/api/auth/register`, `/api/auth/login` — регистрация и выдача JWT-токенов.
  * **Users:** `/api/users/me`, `/api/users/profile`, `/api/users/password` — управление профилем пользователя, загрузка аватарок.
  * **Kuis & Lessons:** `/api/kuis`, `/api/lessons` — выдача списка кюев и уроков для мобильного клиента.
  * **Progress:** `/api/lessons/{id}/progress`, `/api/lessons/{id}/score` — сохранение прогресса прохождения и баллов за игру.
  * **Tuner:** `/api/tuner/result` — сохранение результатов ML-распознавания аккордов.

### `database.py`
**Модели базы данных и подключение.**
Определяет схемы таблиц базы данных в виде классов Python. Включает следующие основные таблицы:
* `User`: Хранит данные пользователей (ID, username, email, хеш пароля, аватарку).
* `Kui`: Информация о кюях (название, автор, сложность, ссылки на аудио и JSON ноты).
* `Lesson`: Конкретные уроки, привязанные к кюям.
* `Progress`: Статус прохождения уроков конкретным пользователем.
* `Performance`: Детализированная статистика игры (точность, попадание в ритм).
* `TunerResult`: История использования тюнера (ML-распознавание аккордов).

### `security.py`
**Модуль криптографии и безопасности.**
* Отвечает за генерацию JWT токенов (`create_access_token`).
* Декодирует токены для авторизации запросов (`decode_access_token`).
* Содержит функции для хеширования пользовательских паролей и их верификации при входе (`get_password_hash`, `verify_password`).

### `seed_lessons.py`
**Скрипт первичной инициализации данных (Seeder).**
Автоматически сканирует директорию с JSON-файлами нот (`../kui_json/`) и аудиофайлами, парсит метаданные (BPM, длительность, количество нот) и заполняет таблицы `Kui` и `Lesson` в базе данных. Это позволяет быстро развернуть приложение на новом сервере с уже готовым контентом.

### `docker-compose.yml` и `Dockerfile`
**Конфигурация инфраструктуры.**
Описывают, как собрать образ сервера и запустить его вместе с базой данных PostgreSQL в изолированной среде. Гарантирует, что проект будет работать одинаково на любом компьютере.

### Вспомогательные скрипты
* `migrate_sqlite_to_postgres.py` — Утилита для безопасного переноса данных пользователей из локальной базы SQLite в рабочую PostgreSQL без потери прогресса.
* `add_avatar_column.py` — Скрипт миграции схемы базы данных (добавление поля для аватарок).

## 3. Архитектура Данных и Взаимодействие (Data Flow)

1. **Мобильный клиент (Flutter)** отправляет HTTP REST запросы на сервер.
2. Запросы, требующие авторизации, включают заголовок `Authorization: Bearer <token>`.
3. Функция `get_current_user` в `main.py` перехватывает токен, передает его в `security.py` для валидации и достает ID пользователя.
4. Сервер обращается к PostgreSQL через ORM `database.py`.
5. Результат возвращается на клиент в формате JSON, предварительно пройдя валидацию через Pydantic-схемы (например, `UserResponse`, `KuiOut`).

## 4. Особенности реализации для Диплома
* **Безопасность:** Пароли не хранятся в открытом виде. Используется современный алгоритм bcrypt, который устойчив к атакам перебором.
* **Масштабируемость:** База данных нормализована. Разделение сущностей `Progress` (статус урока) и `Performance` (оценка конкретной игры) позволяет анализировать динамику обучения пользователя.
* **Хранение файлов:** Медиафайлы (mp3, png) не хранятся в базе данных, чтобы не перегружать ее. Они лежат в файловой системе (`storage/`), а в БД записываются только пути к ним (`audio_url`, `avatar_url`), что является индустриальным стандартом.
